> 先生からの指示:
> 「コード実行中の動作が理解できるような動画がプレゼンの中であればリアル感が出る」
>
> 過年度の資料（`西島プレゼン最終.pptx`）には**動画が10本**埋め込まれており、
> この研究室では「動作映像」で見せるのが定着した型になっている。

この文書は**柴尾さんが手を動かす部分**の手順書。上から順にやれば動画が完成する。

## 0. 全体像

> **実際に採用したのは②のみ**（2026-09-23 時点）。
> ①③のスライドは削除し、発表では**②を1本だけ**流す構成に変更した。

当初の計画は3本。合計で発表の3分半を占める想定だった。

| 動画 | 内容 | 長さ | 採否 |
| --- | --- | --- | --- |
| ① | LabVIEWから単体AIに送って返ってくる | 30秒 | 見送り（②と口頭で足りるため） |
| ② | LabVIEWから1回送って3体のAIが会話する | 60秒 | **採用（スライド9）** |

## 1. 撮影プランを選ぶ

サーバーはMac、LabVIEWは研究室のWindows機、と分かれているのが悩みどころ。
「コードが動いている様子」を見せるには、**LabVIEWの画面とサーバーのログを同じ映像に入れたい**。

### プランA（推奨）：Windows 1台で完結させる

WindowsにDocker Desktopを入れてサーバーもWindows側で動かす。
そうすると **LabVIEWとサーバーログが同じ画面に並ぶ**ので、録画が1回で済む。

- 利点：録画が簡単、映像として一番わかりやすい
- 利点：**動画③（移植性の検証）も同時に完了する**。先生が気にしていた「別PCで動くか」の宿題がこれで片付く
- 欠点：Windowsのセットアップに1時間ほどかかる可能性

> 手順は `docs/lab_setup_guide.md` の「3.5 Windows で動かす場合」を見る。
> Node.js も Git も不要で、**ZIPダウンロード＋Docker Desktop だけ**。
> 以前 `git` / `npm` / `winget` が使えず詰まったが、この経路ならそれらを回避できる。

### プランB（保険）：2台を同時に録画して後で合成

Windows側でLabVIEW画面を、Mac側でサーバーログを、同時に録画して横に並べる。

- 利点：セットアップ不要、今すぐ撮れる
- 欠点：2つの映像の時刻合わせが必要（合成用スクリプトを用意してあるので手間は小さい）

**まずプランAを試して、うまくいかなければプランBに切り替える**のがよい。

## 2. 撮影前の準備（共通）

### 2-1. 画面をきれいにする

録画に映るので、事前に整えておく。

- [ ] デスクトップの不要なウィンドウを閉じる
- [ ] 通知をオフにする（Windows: `Win + N` → 集中モード／Mac: 通知センターで「おやすみモード」）
- [ ] ブラウザのブックマークバーに個人情報が映らないようにする（前回の動画では映っていた）
- [ ] **APIキーが画面に映らないことを確認**する。`.env.local` は絶対に開かない
- [ ] LabVIEWのフロントパネルの文字を大きくする（発表で読めるように）
  - 制御器を選択 → ツールバーのフォントサイズを **18pt以上**に
- [ ] ターミナルの文字も大きくする
  - Windows Terminal: `Ctrl` + マウスホイール上
  - Mac ターミナル: `Cmd` + `+` を数回

### 2-2. 入力する文章を決めておく

その場で考えると間が空くので、**事前にメモ帳に用意してコピペ**する。

動画①用（単体AI）:
```txt
今日のリハビリはどうでしたか？
```

動画②用（3体のAI）— **リハビリの文脈にする**と研究との繋がりが伝わる:
```txt
リハビリのトレーニングを終えました。指が少し動きやすくなった気がして、続けられそうです。
```

### 2-3. 1回リハーサルする

本番前に必ず1回通す。ここで以下を確認する。

- [ ] サーバーが起動していて、ログが流れるのが見える
- [ ] LabVIEWから送信して返信が来る
- [ ] **3体のときにタイムアウトしない**（LabVIEWのHTTP POSTのタイムアウトを `120000` ms にしてあるか確認）
- [ ] 返信が想定どおり「前の発言を受けた」内容になっている
  - なっていなければ、内容が良くなるまで数回試して、良い回を本番にする

## 3. 録画する

### 3-1. Windows での録画（Xbox Game Bar）

Windows 10/11に標準で入っている。インストール不要。

1. 録画したいウィンドウ（LabVIEW）をクリックしてアクティブにする
2. `Win` + `G` を押す → Game Bar が開く
3. 「キャプチャ」ウィジェットの**録画ボタン（●）**を押す
   - もしくは `Win` + `Alt` + `R` で直接録画開始
4. 操作する
5. `Win` + `Alt` + `R` で停止
6. 保存先：`C:\Users\<ユーザー名>\Videos\Captures\`

> **Game Bar が「ゲーム機能は利用できません」と出る場合**
> 設定 → ゲーム → Xbox Game Bar をオンにする。
> それでもダメなら Windows 11 の「Snipping Tool」に画面録画機能がある（`Win` + `Shift` + `S` → ビデオアイコン）。

### 3-2. Mac での録画

1. `Cmd` + `Shift` + `5` を押す
2. 「選択部分を収録」を選び、録画したい範囲をドラッグで指定
3. 「収録」をクリック
4. 停止はメニューバーの■、または `Cmd` + `Ctrl` + `Esc`
5. デスクトップに `.mov` で保存される

### 3-3. 動画①の撮り方（単体AI・30秒）

画面レイアウト：**左にLabVIEWフロントパネル、右にサーバーのログ**

```txt
┌─────────────────┬──────────────┐
│  LabVIEW        │  サーバーログ  │
│  フロントパネル   │  （ターミナル） │
│                 │              │
│  User Text: [ ] │              │
│  Agent ID: [ ]  │              │
│  Reply:    [ ]  │              │
└─────────────────┴──────────────┘
```

撮影の流れ（各ステップの間に**1秒止める**。忙しない映像は読めない）:

1. 録画開始。2秒間そのまま静止（編集で切りやすくなる）
2. User Text に文章を貼り付ける
3. Agent ID が `alpha` になっているのを見せる
4. **Run（▶）をクリック**
5. 右のログにリクエストが出るのを2秒見せる
6. Reply に返信が表示される
7. 返信を2秒見せて録画停止

### 3-4. 動画②の撮り方（3体の会話・60秒）【最重要】

同じレイアウト。**マルチ用のVI**（`/api/lv/multi` を叩くほう）を使う。

1. 録画開始。2秒静止
2. User Text にリハビリの文章を貼り付ける
3. **Run をクリック**
4. **ここが見せ場**：右のログに、AIが1体ずつ順番に呼ばれていく様子が流れる。
   ここは早送りせず、**そのままの速度で見せる**（約6秒）
5. Transcript に3体分の会話がまとめて表示される
6. **表示された会話を上から下へゆっくりスクロール**して、3体が順番に話しているのを見せる
7. 2秒静止して録画停止

> **ポイント**：発表では「2体目が『ただし』と受けている」と説明する。
> スクロール時にその部分で**一瞬止める**と、聞き手の視線が合う。

### 3-5. 動画③の撮り方（Docker起動・40秒）

プランAでWindowsセットアップをした場合、その様子をそのまま撮ればよい。

1. 録画開始
2. エクスプローラーで、ZIPを展開したフォルダを見せる（Node.jsもGitも入っていないPCであることを口頭で言う）
3. そのフォルダでコマンドプロンプトを開く
4. `docker compose up --build` と入力して実行
5. ビルドのログが流れる → **ここは編集で4倍速に早送りする**（コマンドは後述）
6. `Ready on http://localhost:3000` のような起動完了メッセージを見せる
7. ブラウザまたはLabVIEWから応答が返ることを見せて停止

## 4. 編集する

編集用のスクリプトを `scripts/make_demo_video.sh` に用意してある。
Mac のターミナルで実行する（Windowsで撮った動画もMacに移してから処理すればよい）。

### 4-1. 使い方

```bash
cd ~/Desktop/Trilogue

# 使えるコマンドの一覧を表示
bash scripts/make_demo_video.sh help
```

### 4-2. よく使う操作

**PowerPoint用に変換する（必ず最後にやる）**

```bash
bash scripts/make_demo_video.sh convert 入力.mov demo1.mp4
```

`.mov` のままだと**Windowsのパソコンで再生できない**ことがある。
発表用PCがWindowsの可能性があるので、**必ずmp4（H.264）に変換**しておく。

**いらない部分を切る**

```bash
# 3秒地点から30秒間を切り出す
bash scripts/make_demo_video.sh trim 入力.mp4 demo1.mp4 3 30
```

**早送りする（動画③のビルドログなど）**

```bash
# 4倍速にする
bash scripts/make_demo_video.sh speed 入力.mp4 demo3.mp4 4
```

**2つの動画を横に並べる（プランBの場合）**

```bash
# 左にLabVIEW、右にサーバーログ。最後の数字は右側の開始をずらす秒数（時刻合わせ用）
bash scripts/make_demo_video.sh side labview.mp4 server.mov demo2.mp4 1.5
```

時刻がずれていたら、最後の数字を調整して何度か試す。

**ファイルサイズを小さくする**

```bash
bash scripts/make_demo_video.sh compress 入力.mp4 demo2.mp4
```

> 目安：**1本 20MB以下**にする。
> 過年度の `西島プレゼン最終.pptx` は動画10本で121MBだった。
> 3本なら60MB以内に収めたい。

## 5. PowerPointに埋め込む

### 5-1. 挿入手順

1. 動画を入れるスライドを開く
2. リボンの **挿入** → **ビデオ** → **このデバイス...**（Macは「ビデオ」→「ムービー（ファイルから）」）
3. mp4を選ぶ

> **「リンク」ではなく「埋め込み」にする**。
> リンクにすると、別のPCで開いたときに動画が再生されない。
> Windows版では挿入ボタンの横の▼から「ファイルに挿入」（＝埋め込み）を選ぶ。

### 5-2. 自動再生にする

動画をクリックしてから、**再生**タブ → **開始** を「**自動**」にする。
クリックして再生する方式だと、発表中に間が空いて締まらない。

### 5-3. 見やすくする設定

- 動画を選択 → 再生タブ → **「全画面再生」はオフ**のまま（説明文と一緒に見せたい）
- **「再生が終了したら巻き戻す」にチェック**（質疑でもう一度見せるとき楽）
- 動画の下に1行の説明テキストを置く（例：「LabVIEWから1回送信 → 3体のAIが順番に発言」）

### 5-4. 動作確認【必ずやる】

- [ ] スライドショーを最初から通しで実行して、3本すべてが自動再生されるか確認
- [ ] **発表で使う実機**（研究室のPC）にファイルを移して、そこでも再生できるか確認
- [ ] USBメモリで持ち込む場合、コピー後のファイルで再生確認
- [ ] 音声が入っていないか確認（不要なら 再生タブ → 音量 → ミュート）

## 6. 万一の保険

動画が再生できない事故は発表でよくある。以下を用意しておく。

1. **各動画の決定的な瞬間のスクリーンショット**を撮っておき、補足スライドに入れる
   - 動画②なら「3体の返信が表示された画面」
2. 動画ファイル単体もUSBに入れておく（PowerPointで再生できなければ直接開く）
3. 最終手段として**その場で実演できる状態**にしておく
   - ただしネットワークに繋がらないリスクがあるので、あくまで最後の手段
