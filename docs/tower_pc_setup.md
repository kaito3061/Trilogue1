# 検証用タワー PC のセットアップ手順と記録

控室にある、松田先生がキープしているタワー PC を、Trilogue の検証用 Windows 機にするための手順。
**Windows が起動しなければ、Windows 10 をクリーンインストールする**（2026-10-28、先生の了承済み）。

各ステップの「記録」欄は、作業しながらその場で埋める。
終わったら、ハマったことを `docs/integration_notes.md` に、再現試験の結果を `docs/reproduction_test.md` に移す。

パスワードやプロダクトキーは、この文書にもリポジトリにも書かない。

2. 結果で分かれる

## STEP 2. インストール用の USB を作る（30〜60分）

**作業用の Windows PC でやるのが一番簡単である。**

1. 作業用 PC で、Microsoft の Windows 10 のダウンロードページを開く
   - 検索するなら「Windows 10 ダウンロード Microsoft」。`microsoft.com` のページであることを確かめる
2. **ツールを今すぐダウンロード**（メディア作成ツール、Media Creation Tool）を押して実行する
3. 「別の PC のためにインストールメディアを作る」を選ぶ
4. 言語は日本語、エディションは Windows 10、アーキテクチャは **64 ビット**
5. 「USB フラッシュドライブ」を選び、挿した USB を選ぶ
6. ダウンロードと書き込みが終わるまで待つ（ネットの速さで20〜60分）

Mac しか無い場合: 同じページを Mac で開くと ISO ファイルのダウンロードになる。
ただし、Mac で起動できる USB にするには、大きいファイルを分割するなどの追加の作業が要る。
**研究室の Windows 機を借りて作る方が早い。** どうしても Mac でやるときは、
「Mac で Windows 10 の起動 USB を作る方法」を今の日付で AI に聞く。

サポート終了後のため、ダウンロードページが無くなっている・変わっている可能性がある。
そのときは「Windows 10 22H2 のインストールメディアを公式に入手する方法」を AI に聞き、
**Microsoft の公式サイトから入手する方法だけ** を使う（非公式の配布サイトは使わない）。

## STEP 3. USB から起動する（10〜20分）

1. タワー PC に USB を挿し、電源を入れる
2. すぐに **起動メニューのキー** を連打する。メーカーで違う

| メーカー | よくあるキー |
| --- | --- |
| Dell・Lenovo | `F12` |
| HP | `F9`（または `Esc` のあと `F9`） |
| ASUS | `F8` |
| MSI | `F11` |
| 自作・その他 | 起動直後の画面の下に `Boot Menu` のキーが出ていることが多い |

3. 出てきた一覧から USB（`UEFI: メーカー名` のような名前）を選ぶ
4. Windows のセットアップ画面が出れば成功

出ないとき: BIOS（起動直後に `Del` や `F2`）の **Boot** の項目で、USB を一番上にする。
「Secure Boot」で止まる場合も BIOS の設定を見る。分からなければ画面の写真を撮って AI に聞く。

## STEP 4. Windows 10 をクリーンインストールする（30〜60分）

1. 言語・キーボードは日本語のまま **次へ** → **今すぐインストール**
2. 「プロダクトキーの入力」→ **プロダクトキーがありません**
   - 以前この PC で Windows 10 が認証されていれば、インストール後にネットに繋ぐと自動で認証されることが多い
3. エディションの選択 → **元の Windows と同じ版**（Home か Pro）を選ぶ。違う版を選ぶと認証されない
4. ライセンスに同意 → **カスタム: Windows のみをインストールする**
5. ドライブの一覧で、Windows が入っていたディスクのパーティションを **全部削除** し、「割り当てられていない領域」を選んで **次へ**
   - **ディスクが複数ある場合は、消す前にどれがどれか確認する。** 容量で見分ける。迷ったら止めて写真を撮る
6. インストールが進む。途中で何度か再起動する。USB は抜かなくてよいが、再起動後にまたセットアップの最初に戻ってしまったら USB を抜く
7. 初期設定
   - 地域・キーボードは日本
   - **アカウントは、研究室で決めた名前のローカルの管理者アカウントにする**（名前とパスワードは先生と相談する。ここには書かない）
     - Microsoft アカウントを求められて先に進めないときは、LAN ケーブルを一度抜くと「オフラインアカウント」や「制限付きエクスペリエンス」が選べることがある
   - プライバシーの設定は全部オフでよい
8. デスクトップが出たら、LAN ケーブルを挿す

## STEP 5. インストール後の確認（30〜60分）

| 確認すること | 見方 | 結果 |
| --- | --- | --- |
| ネットに繋がっているか | ブラウザで何かのサイトを開く | |
| 認証されているか | 設定 → 更新とセキュリティ → ライセンス認証 | |
| Windows のバージョン | `Windows + R` → `winver`。**22H2（ビルド 19045）** になっているか | |
| Windows Update | 設定 → 更新とセキュリティ → Windows Update → 更新プログラムのチェック。終わるまで繰り返す | |
| 足りないドライバー | スタートを右クリック → デバイスマネージャー。黄色い「!」が無いか | |
| 仮想化 | タスクマネージャー → パフォーマンス → CPU → 「仮想化: 有効」 | |

よくあること:

- **LAN に繋がらない** … ネットワークのドライバーが入っていない。作業用 PC で、メーカーのサイトから型番に合うドライバーを落とし、USB で運んで入れる
- **認証されない** … 版を間違えた、または以前この PC で認証されていなかった。本体のシールのキーを入れるか、先生に相談する
- **仮想化が無効** … `docs/user_manual.md` の 2-1 の「仮想化を有効にする」

Windows 10 はサポートが終わっていて、セキュリティの更新が来ない。
**研究室の LAN の中での検証専用とし、大事なデータは置かない。**

## STEP 6. Trilogue を入れる（マニュアルの再現試験を兼ねる）

ここからは `docs/user_manual.md` の手順そのものである。**マニュアルだけを見て進め、止まったところを記録する。**
記録は `docs/reproduction_test.md` の用紙を使う。

1. ZIP を落として展開（マニュアル節1）
2. Docker Desktop を入れる（節2-1）
   - **Windows 10 で動く版か確かめる。** Docker Desktop の公式の System requirements を見る。
     最新版が Windows 10 に対応していなければ、公式のリリースノートから、Windows 10 に対応している最後の版を入れる。
     このとき起きたことは、必ず `docs/integration_notes.md` に書く
3. APIキーを置く（節3）
4. サーバーを起動し、ブラウザで `http://localhost:3000/api/lv/agents` を開く（節4）
5. LabVIEW から繋ぐ（節5）
   - このタワーに LabVIEW が入っていなければ、研究室の別の Windows 機の LabVIEW から、LAN 越しにこのタワーへ繋ぐ
   - LabVIEW を入れる場合はライセンスが必要なので、先生に確認する
   - LabVIEW が無くても、`python3 scripts/lv_roundtrip_check.py --base-url http://<タワーのIP>:3000` で同じ往復を確かめられる（Python が要る）
