# 連携時のノウハウ記録

環境構築や、LabVIEW・サーバー・LLM をつなぐときに **実際にハマったこと** と、その抜け方を残す。
手順そのものは `docs/user_manual.md` にある。ここは「手順どおりにやったのに止まった」ときに見る。

書き方のルール:

- 起きたことだけを書く（推測で「こうなるはず」は書かない）
- 日付、環境（OS・PC）、見えていた文言、原因、どう抜けたか、の順に書く
- 新しくハマったら、該当する節の表に1行足す。節が無ければ作る
- APIキーの中身は書かない

## 3. ネットワーク（LabVIEW 機とサーバー機が別の PC のとき）

| 日付 | 環境 | 見えていたこと | 原因 | どう抜けたか |
| --- | --- | --- | --- | --- |
| 2026-08 | サーバー: 自宅 Wi-Fi の Mac、LabVIEW: 研究室の Windows | LabVIEW から繋がらない | 2台が別のネットワークにいた（自宅 Wi-Fi と学内 LAN）。この方式は同じネットワーク内でしか届かない | 2台を同じ Wi-Fi（同じルーター）に繋いだ。`192.168.3.x` のように、IP の前3つがそろっているかで確かめられる |
| 2026-08 | 同上 | 昨日まで繋がっていたのに繋がらない | Wi-Fi に繋ぎ直すと、サーバー機の IP が変わることがある | サーバー機で IP を確認し直し、LabVIEW の `Base URL` を書き換えた |
| 2026-08 | Windows | `ifconfig` が無い | Windows のコマンドは `ipconfig` | `ipconfig` の `IPv4 アドレス` を見た |
| 2026-08 | 別 PC から接続 | ブラウザで `/api/lv/agents` が開かない | サーバー機のファイアウォールが 3000 番を止めていた | 初回に出る「アクセスを許可しますか」で許可した |
| 2026-11-04 | サーバー: N100（Windows 11 Home、Docker）、接続元: Mac | N100 自身では `/api/lv/agents` が開くのに、Mac から `curl` すると `Couldn't connect to server` | 許可のダイアログが出ず、ファイアウォールが 3000 番を止めていた | 「セキュリティが強化された Windows Defender ファイアウォール」の受信の規則に、TCP 3000 を許可する規則を手で追加した |

実測: 研究室の Windows 機の LabVIEW → LAN → サーバー機で、3体の往復が約4.7秒（2026-08）。

切り分けの順番: まず LabVIEW 機のブラウザで `http://<サーバーIP>:3000/api/lv/agents` を開く。
開かなければネットワークかサーバーの問題で、LabVIEW の問題ではない。

## 4. LabVIEW（HTTP と JSON）

| 日付 | 見えていたこと | 原因 | どう抜けたか |
| --- | --- | --- | --- |
| 2026-08 | `Unflatten From JSON` で `The cluster element was not found in the JSON` | 受け取り用クラスタに、JSON に無い名前が残っていた。1体用の VI を複製したため `reply` などが残っていた | クラスタを `ok` / `transcript` / `error` の3つだけにした。まず `ok` 1つだけで通るか試すと切り分けやすい |
| 2026-11-04 | N100（LabVIEW 2026 Q3 Community）で `chat.vi` を実行すると `The VI comes from an untrusted location` | ネットから落とした ZIP の VI は「信頼されていない場所」扱いになる | `View > Manage Trusted Files` で `labview` フォルダを追加した。そのあと `chat.vi` で返事が出た |


手順書を書く段階で先回りして入れた注意（実際に起きたかは記録が無い。起きたら上の表に移す）:

| 起きうること | 原因 | 避け方 |
| --- | --- | --- |
| 3体のときだけ、たまにエラーになる | `POST` の `timeout (ms)` の既定は 10 秒。3体で返事が長いと超えうる | `timeout (ms)` に `120000` を繋ぐ |
| `Unflatten From JSON` のエラーが消えない | ラベルではなくキャプションを書き換えている。JSON のキーになるのはラベル | 右クリック → `Visible Items > Label` でラベルを確認する |
| 「rounds は 1〜3 の整数で」というエラー | クラスタに `rounds` を入れると、未入力でも既定値 0 が送られる | `rounds` はクラスタに入れない（省略すれば1巡） |
| Case Structure の出口で配線が壊れる | True と False で別々の出力トンネルを作っている | 出力トンネルを1つにし、両方から同じトンネルへ繋ぐ |
| SubVI にしようとしても `Show Connector` が出ない | ブロック図側のアイコンを右クリックしている | コネクタペーンはフロントパネル側にしかない。`Ctrl + E` で移ってから右クリック |
| `.env.local` を作ったのに Docker が「無い」と言う | 拡張子が隠れていて `.env.local.txt` になっている | 「表示 → ファイル名拡張子」で名前を確認する |

教訓: LabVIEW 側でエラーが出たら、先に `python3 scripts/lv_roundtrip_check.py` を通す。
これが `ALL PASS` なら、サーバーは正常で、直すのは LabVIEW 側だけである。

## 5. LLM の API

| 日付 | 環境 | 見えていたこと | 原因 | どう抜けたか |
| --- | --- | --- | --- | --- |
| 2026-10-28 | Mac、大学のネットワーク | 実験の途中で、全モデルの呼び出しが一斉に失敗した。サーバーのログに `ENOTFOUND` と `Request timed out` | ネットワークが一時的に切れていた（OpenAI のサーバー名が引けない）。モデルやキーの問題ではない | 失敗した回を捨てて流し直した。1体の失敗で会話全体は落ちず、`ok:false` として記録されていた |
| 2026-10-28 | Mac の Python（python.org 版） | Python から直接 OpenAI を呼ぶと `CERTIFICATE_VERIFY_FAILED` | python.org 版の Python は、最初は証明書が入っていない | `curl` で確認した。Python を使うなら、Python のフォルダにある `Install Certificates.command` を一度実行する。サーバー（Docker）には関係ない |
| 2026-10-28 | OpenAI API | `gpt-5-mini` は1発言に8〜10秒かかった（`gpt-4o-mini` は1〜2秒） | モデルの違い | 応答時間が大事な画面では、速いモデルを使う。実験では、モデルごとの秒数を記録しておく |

エラー文の読み方（サーバーが返す `error`）:

| 文言 | まず疑うこと |
| --- | --- |
| LLM の利用上限に達しました | 残高切れ、または短時間に送りすぎ |
| LLM の呼び出しに失敗しました | キーの間違い、ネットワーク切れ。サーバーのログに `401` があればキー |
| OPENAI_API_KEY が設定されていません | `.env.local` の場所・名前・中身 |

## 6. 公開リポジトリの管理

| 日付 | やったこと | 理由 |
| --- | --- | --- |
| 2026-09-24 | 研究室向けの公開リポジトリ（Trilogue1）には、コードと引き継ぎに必要な資料だけを置き、発表資料・報告書・研究途中の資料は非公開の方に置いた | 公開側を見た人が迷わないように。研究途中の結果や内部の資料を外に出さないため |
